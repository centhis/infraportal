# Чеклист для ручного тестирования Frontend

## 1. Аутентификация

### 1.1. Локальная аутентификация

- [ ] **Test Case 1.1.1: Успешный вход**
1.  Перейти на страницу входа (`/login`).
2.  Ввести логин и пароль существующего локального пользователя (например, `admin`).
3.  Нажать кнопку "Войти".
4.  **Ожидаемый результат:** Пользователь успешно авторизован и перенаправлен на главную страницу (`/home`). В правом верхнем углу отображается аватар пользователя.

- [ ] **Test Case 1.1.2: Неуспешный вход (неверный пароль)**
1.  Перейти на страницу входа (`/login`).
2.  Ввести логин существующего локального пользователя (например, `admin`).
3.  Ввести неверный пароль.
4.  Нажать кнопку "Войти".
5.  **Ожидаемый результат:** Появляется сообщение об ошибке "Incorrect login or password". Пользователь остается на странице входа.

- [ ] **Test Case 1.1.3: Выход из системы**
1.  Авторизоваться в системе.
2.  Нажать на аватар пользователя в правом верхнем углу.
3.  В выпадающем меню выбрать "Выйти".
4.  **Ожидаемый результат:** Пользователь выходит из системы и перенаправляется на страницу входа.

### 1.2. LDAP аутентификация (если настроено)

- [ ] **Test Case 1.2.1: Успешный вход**
1.  Убедиться, что интеграция с LDAP включена в настройках.
2.  Перейти на страницу входа (`/login`).
3.  Ввести логин и пароль существующего пользователя в LDAP.
4.  Нажать кнопку "Войти".
5.  **Ожидаемый результат:** Пользователь успешно авторизован и перенаправлен на главную страницу.

- [ ] **Test Case 1.2.2: Неуспешный вход (неверные учетные данные)**
1.  Перейти на страницу входа (`/login`).
2.  Ввести логин существующего пользователя в LDAP.
3.  Ввести неверный пароль.
4.  Нажать кнопку "Войти".
5.  **Ожидаемый результат:** Появляется сообщение об ошибке. Пользователь остается на странице входа.

- [ ] **Test Case 1.2.3: Вход, когда LDAP отключен**
1.  Убедиться, что интеграция с LDAP выключена в настройках.
2.  Попытаться войти с учетными данными пользователя LDAP.
3.  **Ожидаемый результат:** Аутентификация не проходит, появляется сообщение об ошибке.

### 1.3. LDAP Синхронизация и Пограничные случаи

*Предусловие: Эти тесты требуют доступа к LDAP-серверу для имитации изменений.*

- [ ] **Test Case 1.3.1: Первый вход нового пользователя LDAP**
1.  Создать нового пользователя непосредственно в LDAP.
2.  Убедиться, что этого пользователя нет в локальной базе данных Infraportal.
3.  На странице входа Infraportal ввести учетные данные нового пользователя.
4.  **Ожидаемый результат:**
    *   Пользователь успешно аутентифицируется.
    *   Новая запись для этого пользователя создается в локальной базе данных Infraportal.
    *   Пользователю назначаются группы по умолчанию, если они настроены для авто-назначения LDAP пользователям.
    *   Пользователь перенаправляется на главную страницу.

- [ ] **Test Case 1.3.2: Пользователь переименован в LDAP**
1.  Авторизоваться в Infraportal как существующий пользователь LDAP (`ldap_user_1`).
2.  Выйти из системы.
3.  В LDAP, переименовать пользователя `ldap_user_1` в `ldap_user_2`.
4.  Попробовать войти в Infraportal с новыми учетными данными (`ldap_user_2`).
5.  **Ожидаемый результат:** Успешный вход. Существующая запись пользователя в Infraportal должна обновиться, отражая новое имя, а не создавать нового пользователя.
6.  Попробовать войти со старыми учетными данными (`ldap_user_1`).
7.  **Ожидаемый результат:** Вход не удался.

- [ ] **Test Case 1.3.3: Пользователь перемещен в другой OU в LDAP**
1.  Авторизоваться в Infraportal как существующий пользователь LDAP, находящийся в `OU=Users,DC=example,DC=com`.
2.  Выйти из системы.
3.  В LDAP, переместить этого пользователя в `OU=ArchivedUsers,DC=example,DC=com`.
4.  Предположим, что `LDAP_BASE_DN` в настройках Infraportal указывает на `OU=Users,DC=example,DC=com`.
5.  Попробовать войти в Infraportal с учетными данными этого пользователя.
6.  **Ожидаемый результат:** Вход не удался, так как пользователь больше не находится в пределах `LDAP_BASE_DN`.

- [ ] **Test Case 1.3.4: Автоматическая синхронизация (запуск задачи Celery)**
1.  В LDAP, создать нового пользователя.
2.  Не выполнять вход этим пользователем.
3.  Дождаться выполнения фоновой задачи синхронизации пользователей LDAP (согласно `LDAP_SYNC_SCHEDULE`).
4.  Перейти в `User Management` -> `Users`.
5.  **Ожидаемый результат:** Новый пользователь из LDAP появился в списке пользователей Infraportal.

- [ ] **Test Case 1.3.5: Деактивация пользователя в LDAP**
1.  В LDAP, деактивировать (заблокировать) учетную запись существующего пользователя.
2.  Дождаться выполнения задачи синхронизации.
3.  В Infraportal, проверить статус этого пользователя в `User Management` -> `Users`.
4.  **Ожидаемый результат:** Пользователь помечен как неактивный (`is_active: false`).
5.  Попробовать войти под этим пользователем.
6.  **Ожидаемый результат:** Вход не удался.

## 3. Права доступа (RBAC) - Расширенное тестирование

Этот раздел описывает оптимальный способ тестирования прав доступа с созданием минимального количества ролей и пользователей.

### 3.1. Подготовка тестовых ролей и пользователей

*Предусловие: все действия по подготовке выполняются под пользователем `admin`.*

1.  **Создание роли "Viewer":**
    *   Перейти в `User Management` -> `Roles`.
    *   Нажать `Add Role`.
    *   Имя: `Viewer`.
    *   Выбрать разрешения: `users:view`, `settings:view`.
    *   Сохранить роль.

2.  **Создание роли "User Manager":**
    *   Аналогично создать роль с именем `User Manager`.
    *   Выбрать разрешения: `users:view`, `users:create`, `users:update`, `users:delete`.
    *   Сохранить роль.

3.  **Создание роли "Settings Manager":**
    *   Аналогично создать роль с именем `Settings Manager`.
    *   Выбрать разрешения: `settings:view`, `settings:update`.
    *   Сохранить роль.

4.  **Создание тестовых пользователей:**
    *   Перейти в `User Management` -> `Users`.
    *   Создать трех пользователей: `test_viewer`, `test_user_manager`, `test_settings_manager`.
    *   Создать три группы: `group_viewer`, `group_user_manager`, `group_settings_manager`.
    *   Назначить каждой группе соответствующую роль (группе `group_viewer` -> роль `Viewer` и т.д.).
    *   Назначить каждого пользователя в соответствующую группу (`test_viewer` -> в `group_viewer` и т.д.).

- [ ] **Test Case 3.2: Тестирование под ролью "Viewer"**

1.  Войти в систему под пользователем `test_viewer`.
2.  **Ожидаемый результат:**
    *   В меню навигации видны пункты `User Management` и `Settings`.
    *   **User Management:**
        *   Можно просматривать списки пользователей, групп и ролей.
        *   Кнопки "Add", "Edit", "Delete" (и иконки) отсутствуют или неактивны.
        *   При клике на строки в таблицах ничего не происходит (или открывается форма в режиме read-only).
    *   **Settings:**
        *   Можно просматривать `Core` и `LDAP` настройки.
        *   Все поля заблокированы для редактирования.
        *   Кнопки "Save" и "Test Connection" отсутствуют или неактивны.

- [ ] **Test Case 3.3: Тестирование под ролью "User Manager"**

1.  Войти в систему под пользователем `test_user_manager`.
2.  **Ожидаемый результат:**
    *   В меню навигации виден пункт `User Management`, но отсутствует пункт `Settings`.
    *   **User Management:**
        *   Полный доступ к управлению пользователями, группами и ролями.
        *   Все кнопки "Add", "Edit", "Delete" активны и функциональны.
        *   Можно создавать, изменять и удалять сущности (кроме `built-in`).
    *   **Settings:**
        *   При попытке прямого перехода по URL (`/settings/core`) отображается ошибка доступа.

- [ ] **Test Case 3.4: Тестирование под ролью "Settings Manager"**

1.  Войти в систему под пользователем `test_settings_manager`.
2.  **Ожидаемый результат:**
    *   В меню навигации виден пункт `Settings`, но отсутствует пункт `User Management`.
    *   **User Management:**
        *   При попытке прямого перехода по URL (`/user-management/users`) отображается ошибка доступа.
    *   **Settings:**
        *   Можно просматривать `Core` и `LDAP` настройки.
        *   Поля активны для редактирования, кнопки "Save" и "Test Connection" активны и функциональны.

- [ ] **Test Case 3.5: Тестирование защиты встроенных сущностей**
1.  Войти под `admin`.
2.  Перейти в `User Management` -> `Users`, `Groups`, `Roles`.
3.  Найти встроенные (`built-in`) сущности (например, пользователь `admin`, группа `admin-group`).
4.  **Ожидаемый результат:**
    *   Кнопка или иконка удаления для `built-in` сущностей отсутствует или неактивна.
    *   При попытке редактирования `built-in` роли или группы, можно менять только некоторые поля (например, добавлять разрешения/роли), но не имя.
    *   При попытке редактирования `built-in` пользователя, критичные поля (логин, тип) заблокированы.
