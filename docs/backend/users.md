# Управление Пользователями и RBAC

Модуль `app/users` отвечает за все аспекты, связанные с пользователями, группами, ролями и разрешениями. Он формирует основу для системы контроля доступа на основе ролей (Role-Based Access Control, RBAC).

## 1. Обзор Архитектуры RBAC

Система RBAC в проекте имеет четкую иерархическую структуру:

1.  **Пользователь (User)**: Субъект, который входит в систему.
2.  **Группа (Group)**: Логическое объединение пользователей (например, "Администраторы", "Редакторы").
3.  **Роль (Role)**: Набор разрешений, описывающий определенную функцию (например, "Управление пользователями").
4.  **Разрешение (Permission)**: Атомарное право на выполнение действия (например, `users:create`).

Связь между ними следующая:
`Пользователь -> привязан к Группам -> Группам назначены Роли -> Ролям даны Разрешения`

Итоговый набор прав пользователя — это объединение всех уникальных разрешений, полученных от всех ролей, которые назначены всем группам, в которых состоит пользователь.

## 2. Структура Модуля `app/users`

Модуль логически разделен на подмодули, каждый из которых отвечает за свою часть домена:
-   `app/users/local/`: Управление "локальными" пользователями (хранящимися в БД).
-   `app/users/groups/`: Управление группами.
-   `app/users/roles/`: Управление ролями.
-   `app/users/permissions/`: Сервис для получения разрешений.
-   `app/users/models.py`: Определения моделей ORM для всех сущностей.

Наличие директории `local` намекает на возможность расширения системы для поддержки других источников аутентификации (например, `ldap`) в будущем.

## 3. Модели Данных (`models.py`)

Четыре основные модели ORM и их связи "многие-ко-многим" определены здесь:
-   `User`: Связан с `Group` через таблицу `user_group_association`.
-   `Group`: Связан с `User` и `Role` через `user_group_association` и `group_role_association`.
-   `Role`: Связан с `Group` и `Permission` через `group_role_association` и `role_permission_association`.
-   `Permission`: Атомарная сущность, связанная с `Role`.

Флаг `built_in: bool` используется во всех моделях и ассоциациях для защиты системных сущностей (например, пользователя `admin`) от случайного удаления или изменения.

## 4. Сервисы (Бизнес-логика)

Каждый подмодуль имеет свой сервисный слой, инкапсулирующий бизнес-логику.

### `UserService` (`local/services.py`)
-   Реализует стандартные CRUD-операции (Create, Read, Update, Delete) для локальных пользователей.
-   При создании и обновлении пользователя хеширует пароль с помощью `argon2`.
-   Защищает встроенных (`built_in`) пользователей от удаления или смены логина.

### `GroupService` (`groups/services.py`)
-   Реализует CRUD для групп.
-   Метод `update_group` позволяет изменять не только описание группы, но и список связанных с ней ролей (по ID).
-   Содержит логику, предотвращающую отвязывание встроенных ролей от встроенных групп, что обеспечивает целостность прав администратора.

### `RoleService` (`roles/services.py`)
-   Аналогичен `GroupService`, но для ролей.
-   Метод `update_role` управляет списком разрешений, связанных с ролью.
-   Также защищает встроенные роли от некорректных изменений.

### `PermissionService` (`permissions/services.py`)
-   Ключевой сервис для системы авторизации.
-   Метод `get_user_permissions(user_id)` выполняет сложный запрос к БД, объединяя все таблицы (`User`, `Group`, `Role`, `Permission`), чтобы собрать полный и уникальный список строковых разрешений для конкретного пользователя.
-   Именно этот список затем встраивается в `access_token` при логине.

## 5. Схемы Данных (Pydantic)

Для каждого подмодуля определены свои схемы для валидации данных API:
-   `Create...Schema`: Схемы для создания новых объектов. Содержат обязательные поля и валидаторы.
-   `Update...Schema`: Схемы для обновления. Все поля опциональны, что позволяет выполнять частичное обновление.
-   `...ResponseSchema`: Схемы для ответа API. Исключают чувствительную информацию, такую как хеш пароля пользователя.
-   `Paginated...Response`: Стандартизированные схемы для ответов, содержащих списки объектов с пагинацией (`total` и `items`).
