# Внутренний API (Internal API)

Внутренний API используется **исключительно** фоновыми воркерами (Celery Worker) для общения с бэкендом.
Эти эндпоинты не предназначены для вызова фронтендом или внешними пользователями.

## Безопасность

*   **Префикс**: `/api/internal`
*   **Защита**: Все запросы должны содержать заголовок `X-API-Key`.
*   **Ключ**: Значение ключа задается в переменной окружения `CELERY_WORKER_API_KEY` как на бэкенде, так и на воркере.

---

## Ресурсы

### 1. Tasks Management (`/api/internal/tasks/`)

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| `PATCH` | `/{execution_id}` | Обновление статуса задачи (`IN_PROGRESS`, `SUCCESS`, `FAILURE`), результата или отправка heartbeats. |
| `GET` | `/stale` | Получение списка задач, которые "зависли" (heartbeat устарел). Используется задачей `system:cleanup_zombie_tasks`. |

---

### 2. Secrets Resolution (`/api/internal/settings/`)

Позволяет воркеру безопасно получать чувствительные настройки (пароли и т.д.) только для тех задач, которым это разрешено.

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| `POST` | `/secrets` | Принимает `task_type`. Возвращает словарь `{key: value}` с секретами, разрешенными для этого типа задачи (через `TaskSecretMapping`). |

---

### 3. Users Synchronization (`/api/internal/users/`)

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| `POST` | `/sync_ldap` | Принимает пакет (список) пользователей, полученных из LDAP, для массового обновления/создания в локальной базе данных. |
