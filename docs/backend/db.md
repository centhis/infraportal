# База Данных и Миграции

Этот документ описывает архитектуру слоя доступа к данным, включая настройку базы данных, использование SQLAlchemy ORM и управление миграциями схемы с помощью Alembic.

## 1. Обзор

Слой данных использует следующий стек технологий:

-   **PostgreSQL**: В качестве реляционной базы данных (предполагается по стандарту для `DATABASE_URL`).
-   **SQLAlchemy**: В качестве ORM (Object-Relational Mapper) для определения моделей данных в виде Python-классов и взаимодействия с базой данных.
-   **Alembic**: В качестве инструмента для управления миграциями схемы базы данных.

## 2. Настройка и Управление Сессиями (`database.py`)

Файл `app/db/database.py` отвечает за настройку подключения к БД и управление сессиями.

-   **Engine**: Создается единый экземпляр `sqlalchemy.create_engine`, который использует строку подключения `DATABASE_URL` из [конфигурации](core.md#1-конфигурация-configpy).
-   **SessionLocal**: Фабрика `sessionmaker` используется для создания класса `SessionLocal`, экземпляры которого представляют собой отдельные сессии (транзакции) с базой данных.
-   **Зависимость `db_dependency`**: Для интеграции с FastAPI используется генератор `get_db`, который:
    1.  Создает новую сессию (`db = SessionLocal()`).
    2.  Передает (`yield`) ее в эндпоинт или сервисный слой.
    3.  В случае успешного выполнения запроса, изменения фиксируются (`db.commit()`).
    4.  При возникновении исключения, все изменения откатываются (`db.rollback()`).
    5.  Гарантированно закрывает (`db.close()`) сессию после завершения обработки запроса, независимо от результата.

Это обеспечивает надежное управление жизненным циклом сессий, целостностью данных и пулом соединений.

## 3. Модели ORM (`orm_base.py` и `models.py`)

Все модели данных определяются как Python-классы, наследуемые от базового класса `Base`.

### `orm_base.py`

-   **`Base = declarative_base()`**: Создает базовый класс, от которого должны наследоваться все модели ORM. Этот класс собирает метаданные обо всех моделях.
-   **`load_all_models()`**: Уникальная для проекта функция, которая динамически находит и импортирует все файлы `models.py` в приложении. Это необходимо, чтобы Alembic "узнал" обо всех моделях при автоматической генерации миграций.

### Определение Моделей (например, `app/users/models.py`)

Модели определяют структуру таблиц в базе данных:

-   **`__tablename__`**: Указывает имя таблицы в БД.
-   **`Column`**: Определяет колонку таблицы с указанием типа (`Integer`, `String`, `Boolean`, `DateTime`) и ограничений (`primary_key`, `unique`, `nullable`).
-   **`relationship`**: Определяет связи на уровне ORM, позволяя легко навигировать между связанными объектами (например, `user.groups`).
-   **Ассоциативные таблицы**: Для связей "многие-ко-многим" (например, `User` <-> `Group`) создаются отдельные таблицы (`user_group_association`), которые определяются с помощью `sqlalchemy.Table` и содержат внешние ключи к связываемым таблицам.

## 4. Миграции Базы Данных (Alembic)

Alembic используется для отслеживания изменений в моделях ORM и применения этих изменений к схеме базы данных.

### Конфигурация (`alembic.ini` и `alembic/env.py`)

-   **`alembic.ini`**: Основной файл конфигурации, который указывает путь к скриптам миграций и URL базы данных.
-   **`alembic/env.py`**: Скрипт, который Alembic выполняет при каждой команде. Он является мостом между Alembic и приложением FastAPI:
    1.  **Загрузка конфигурации**: Он импортирует объект `settings` из `app.core.config` и программно устанавливает `sqlalchemy.url`.
    2.  **Загрузка моделей**: Вызывает функцию `load_all_models()` из `orm_base.py`.
    3.  **Передача метаданных**: Устанавливает `target_metadata = Base.metadata`.

Эта настройка позволяет Alembic сравнивать текущее состояние базы данных с тем, что определено в Python-моделях, и автоматически генерировать скрипты миграций.

### Рабочий процесс с миграциями

1.  **Внесение изменений**: Разработчик изменяет модель ORM (например, добавляет новую колонку в класс `User`).
2.  **Генерация миграции**: Выполняется команда:
    ```bash
    alembic revision --autogenerate -m "Add new column to User model"
    ```
3.  **Проверка**: Alembic создает новый файл в `alembic/versions/`, содержащий код на Python для применения (`upgrade`) и отката (`downgrade`) изменений. Этот файл следует проверить.
4.  **Применение миграции**: Для обновления базы данных до последней версии выполняется команда:
    ```bash
    alembic upgrade head
    ```
