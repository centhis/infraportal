# Ядро Приложения (Core)

Модуль `app.core` содержит ключевые компоненты, которые не относятся к конкретной бизнес-логике, но необходимы для работы всего приложения. Сюда входят конфигурация, утилиты безопасности и механизм первоначальной загрузки данных.

## 1. Конфигурация (`config.py`)

Управление конфигурацией приложения построено на библиотеке `pydantic-settings`.

-   **Источник**: Настройки загружаются из переменных окружения, которые могут быть определены в файле `.env` в корне бэкенда.
-   **Класс `Settings`**: Все параметры определены в классе `Settings`, что обеспечивает строгую типизацию и валидацию при запуске приложения.
-   **Парсинг**: Некоторые поля, например `ALLOWED_ORIGINS`, проходят дополнительную обработку (преобразование строки в список).

### Ключевые параметры:

-   `API_PREFIX`: Префикс для всех маршрутов API (например, `/api/v1`).
-   `DATABASE_URL`: Строка подключения к базе данных PostgreSQL.
-   `SECRET_KEY`: Секретный ключ для подписи JWT-токенов. **Критически важный параметр для безопасности.**
-   `ALGORITHM`: Алгоритм подписи токенов (например, `HS256`).
-   `DEFAULT_ADMIN_USER` / `DEFAULT_ADMIN_PASSWORD`: Учетные данные для администратора по умолчанию, который создается при первом запуске.

## 2. Безопасность (`security.py` и `jwt_prvider.py`)

Эти модули предоставляют инструменты для аутентификации и обеспечения безопасности.

### JWT Provider (`jwt_prvider.py`)

-   **Класс `JwtProvider`**: Инкапсулирует логику создания и проверки JWT, используя библиотеку `python-jose`.
-   **Создание токена**: Метод `create_token` принимает данные (payload), дельту времени жизни и тип токена (`access` или `refresh`). Он добавляет в payload стандартные поля (`exp`) и подписывает токен, используя `SECRET_KEY` и `ALGORITHM` из конфигурации.
-   **Декодирование токена**: Метод `decode_token` проверяет подпись и срок жизни токена. В случае ошибки выбрасывается `HTTPException` со статусом `401 UNAUTHORIZED`.

### Утилиты Безопасности (`security.py`)

-   **Хеширование паролей**: Используется `passlib` с криптографической схемой `argon2` для надежного хеширования и проверки паролей (`hash_password`, `verify_password`).
-   **Схема OAuth2**: `oauth2_scheme = OAuth2PasswordBearer(...)` интегрирует FastAPI с OAuth2, что позволяет автоматически находить токен в заголовке `Authorization` и отображать форму для ввода токена в интерактивной документации Swagger.
-   **Время жизни токенов**: Здесь определены константы `ACCESS_TOKEN_EXPIRE` (15 минут) и `REFRESH_TOKEN_EXPIRE` (30 дней).

## 3. Первоначальная Загрузка Данных (`initial_data_loader.py`)

Этот механизм обеспечивает первоначальное наполнение базы данных при первом запуске приложения, чтобы система была сразу готова к работе.

### Динамический Загрузчик

-   Функция `load_initial_data` динамически сканирует всю директорию `app` на наличие файлов с именем `initial_data.py`.
-   Каждый найденный файл импортируется как модуль.
-   Если в модуле есть функция `init_data(db: Session)`, она вызывается.

Такой подход позволяет каждому крупному модулю (`users`, `roles` и т.д.) самостоятельно определять свои начальные данные, не изменяя ядро системы.

### Пример: Инициализация Пользователей (`app/users/initial_data.py`)

Этот скрипт является отличным примером работы загрузчика. Он идемпотентно (безопасно для повторных запусков) выполняет следующие действия:

1.  **Создает пользователя-администратора**: Проверяет наличие пользователя с логином `settings.DEFAULT_ADMIN_USER`. Если его нет, создает нового, используя пароль `settings.DEFAULT_ADMIN_PASSWORD`.
2.  **Создает группу "admins"**.
3.  **Создает роль "admin"**.
4.  **Создает базовые разрешения**: `users:view`, `users:create`, `users:update`, `users:delete`.
5.  **Устанавливает связи**:
    -   Назначает все разрешения роли "admin".
    -   Добавляет роль "admin" в группу "admins".
    -   Добавляет пользователя-администратора в группу "admins".

Таким образом, после первого запуска система гарантированно имеет как минимум одного пользователя с полными правами доступа.
