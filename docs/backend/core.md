# Ядро Приложения (Core)

Модуль `app.core` содержит ключевые компоненты, которые не относятся к конкретной бизнес-логике, но необходимы для работы всего приложения. Сюда входят конфигурация, утилиты безопасности и механизм первоначальной загрузки данных.

## 1. Конфигурация (`config.py`)

Управление конфигурацией приложения построено на библиотеке `pydantic-settings`.

-   **Источник**: Настройки загружаются из переменных окружения, которые могут быть определены в файле `.env` в корне бэкенда.
-   **Класс `Settings`**: Все параметры определены в классе `Settings`, что обеспечивает строгую типизацию и валидацию при запуске приложения.
-   **Парсинг**: Некоторые поля, например `ALLOWED_ORIGINS`, проходят дополнительную обработку (преобразование строки в список).

### Ключевые параметры:

-   `API_PREFIX`: Префикс для всех маршрутов API (например, `/api/v1`).
-   `DATABASE_URL`: Строка подключения к базе данных PostgreSQL.
-   `SECRET_KEY`: Секретный ключ для подписи JWT-токенов. **Критически важный параметр для безопасности.**
-   `REDIS_TASK_URL`: URL брокера сообщений (Redis) для Celery.
-   `CELERY_WORKER_API_KEY`: API-ключ для авторизации запросов от воркеров (internal API).
-   `TASK_TIMEOUT`: Тайм-аут по умолчанию для задач (в секундах).

## 2. Безопасность (`security.py` и `jwt_provider.py`)

Эти модули предоставляют инструменты для аутентификации и обеспечения безопасности.

### JWT Provider (`jwt_provider.py`)

-   **Класс `JwtProvider`**: Инкапсулирует логику создания и проверки JWT, используя библиотеку `python-jose`.
-   **Создание токена**: Метод `create_token` принимает данные (payload), дельту времени жизни и тип токена (`access` или `refresh`).
-   **Декодирование токена**: Метод `decode_token` проверяет подпись и срок жизни токена.

### Утилиты Безопасности (`security.py`)

-   **Хеширование паролей**: Используется **`argon2-cffi`** (класс `PasswordHasher`) для надежного хеширования. Библиотека `passlib` полностью удалена.
-   **Функции хеширования**: `hash_password(password)` и `verify_password(plain_password, hashed_password)`.
-   **OAuth2**: `oauth2_scheme` интегрирует FastAPI с OAuth2 для извлечения токенов.

### Шифрование Секретов (Fernet)

Для хранения чувствительных данных (например, `LDAP_BIND_PASSWORD`) используется **обратимое шифрование** на базе `cryptography.fernet`:

-   **Ключ шифрования**: Генерируется из `SECRET_KEY` приложения с помощью PBKDF2HMAC.
-   **Функции**:
    -   `encrypt_value(value: str) -> str` — шифрует строку для безопасного хранения в БД.
    -   `decrypt_value(encrypted_value: str) -> str` — расшифровывает значение при использовании.

```python
from app.core.security import encrypt_value, decrypt_value

# Шифрование перед сохранением в БД
encrypted = encrypt_value("my_ldap_password")

# Расшифровка при использовании
plain = decrypt_value(encrypted)
```

> [!IMPORTANT]
> Fernet обеспечивает симметричное шифрование. Если `SECRET_KEY` изменится, все зашифрованные данные станут недоступны.

## 3. Первоначальная Загрузка Данных (`initial_data_loader.py`)

Этот механизм обеспечивает первоначальное наполнение базы данных при первом запуске приложения, чтобы система была сразу готова к работе.

### Динамический Загрузчик

-   Функция `load_initial_data` динамически сканирует всю директорию `app` на наличие файлов с именем `initial_data.py`.
-   Каждый найденный файл импортируется как модуль.
-   Если в модуле есть функция `init_data(db: Session)`, она вызывается.

Такой подход позволяет каждому крупному модулю (`users`, `roles` и т.д.) самостоятельно определять свои начальные данные.

### 1. Инициализация Пользователей (`app/users/initial_data.py`)
Этот скрипт выполняет Bootstrap системы RBAC:
1.  **Autodiscovery Permissions**: Сканирует весь код на наличие файлов `permissions.py` с переменной `module_permissions` и автоматически регистрирует все найденные разрешения в базе данных.

#### Декларация Разрешений (`permissions.py`)
Каждый модуль объявляет свои разрешения в файле `permissions.py`:
```python
# app/users/permissions.py
module_permissions = [
    {'name': 'users:view', 'description': 'View all users, groups, and roles'},
    {'name': 'users:create', 'description': 'Create users, groups, and roles'},
]
```
Механизм `autodiscover_permissions` в `app/core/permissions_registry.py` сканирует все модули и собирает эти списки в `DISCOVERED_PERMISSIONS`, которые затем сохраняются в БД при старте.

2.  **Admin Provisioning**: Создает пользователя `admin`, роль `admin` и группу `admins`.
3.  **Binding**: Назначает все найденные разрешения роли администратора.

### 2. Права Доступа к Секретам (`app/settings/initial_data.py`)
Определяет, какие **задачи Celery** имеют право запрашивать какие **чувствительные настройки**.
Это реализуется через модель `TaskSecretMapping`.

Пример инициализации:
```python
DEFAULT_PERMISSIONS = [
    # Задача "users:sync_ldap" получает доступ к паролю "LDAP_BIND_PASSWORD"
    ("users:sync_ldap", "LdapSetting:LDAP_BIND_PASSWORD"),
]
```
Без этой записи воркер получит отказ (`403 Forbidden`) при попытке запросить секрет через Internal API.
