# Каталог Обработчиков (Worker Handlers)

В данном разделе описаны все доступные обработчики задач (Handlers), реализованные в `celery_worker`.

## 1. Пользователи (Users)

### `users:sync_ldap`
**Файл**: `handlers/users/sync_ldap.py`
**Описание**: Выполняет пакетную синхронизацию пользователей с LDAP сервером.
- Получает настройки подключения и фильтр от Бэкенда.
- Выкачивает пользователей из LDAP.
- Отправляет их пачкой (`batch`) на внутренний API бэкенда для обновления базы данных.

**Параметры запуска (kwargs)**:
- `ldap_uri`: URI сервера (e.g. `ldaps://ad.example.com`).
- `bind_dn` / `base_dn`: Настройки поиска.
- `user_filter`: LDAP фильтр поиска.
- `attributes_mapping`: Маппинг атрибутов (опционально).

**Секреты**: Требует `LDAP_BIND_PASSWORD`.

## 2. Системные (System)

### `system:cleanup_zombie_tasks`
**Файл**: `handlers/tasks/cleanup.py`
**Описание**: Служебная задача для очистки "зависших" (Zombie) задач.
1. Запрашивает у бэкенда список задач, которые давно не присылали Heartbeat.
2. Проверяет активность этих задач в текущем кластере Celery (`inspector.active()`).
3. Если задача активна на воркере — принудительно завершает её (`revoke(terminate=True)`).
4. Если задача не найдена (воркер упал) — помечает её в БД как `FAILURE`.

**Расписание**: Обычно запускается раз в 5-10 минут.

---

## 3. Тестовые (Debug)

### `test_task`
**Файл**: `handlers/test_handler.py`
**Описание**: Простая задача для проверки работоспособности очереди.
- Принимает любые параметры.
- Возвращает их обратно вместе со статусом `success`.
- Используется для smoke-тестирования инфраструктуры.
